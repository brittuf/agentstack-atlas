Where it fits in an agent build

Agentforce makes most sense when the customer record already lives in Salesforce and the agent's value comes from acting on it. ENGIE's example is instructive because the action is low risk and reversible, which is the right first step for any customer-facing agent that writes data. Per-action pricing also rewards tight design: an agent that resolves a request in two actions costs half as much as one that wanders through four. (Our analysis.)

When to look elsewhere

If you are not a Salesforce customer, adopting a CRM to get an agent is backwards. Small businesses with a few hundred contacts a month will usually be better served by a hosted chat or phone agent. Watch the budgeting rules too: credits that expire unused punish over-buying. (Our analysis.)

A setup outline

  1. Choose one reversible account action (pause, plan change, feature toggle) and one high-volume question type to start.
  2. Map each request to the actions it would consume and estimate monthly credits from your real contact volume.
  3. Authenticate the customer before any action and confirm the change back to them in plain language.
  4. Use the Digital Wallet usage view Salesforce describes to set alerts before the pilot ends.
  5. Compare resolution rate per action with your current cost per contact before expanding.
