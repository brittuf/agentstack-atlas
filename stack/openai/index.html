Where it fits in an agent build

The Travelers case shows where real-time voice models are strongest: a scripted intake with a motivated caller and a clear end state, here an opened claim. The detail worth copying is that Travelers connected the model to its claims systems and internal tools instead of letting it improvise, and kept humans on the complex cases. Maccabi Healthcare's voice agents for booking and information requests follow the same shape, though their source does not name a model vendor. (Our analysis.)

When to look elsewhere

Building directly on a model API means you own telephony, transcription quality, hand-off logic and monitoring. Most small businesses should buy a hosted AI receptionist instead. Several 2026 reviews also report OpenAI's visual Agent Builder is scheduled to shut down on November 30, 2026 while the Agents SDK continues; confirm on OpenAI's site before building on it. (Our analysis.)

A setup outline

  1. Define the intake fields the caller must provide and the single event that counts as success.
  2. Prototype the conversation in text first, then move to the Realtime API once the script holds up.
  3. Connect exactly one system of record and read key facts back to the caller for confirmation.
  4. Offer a transfer to a person at every step, and log every transcript alongside the record it created.
  5. Measure completion rate, transfer rate and downstream data errors weekly.
