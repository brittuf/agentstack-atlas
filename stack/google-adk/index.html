Where it fits in an agent build

Most of our catalog comes from Google Cloud's public list of customer deployments, so ADK is the natural default for teams already on Google Cloud. Genpact's finance agents show the multi-agent case: separate revenue and P&L agents that coordinate through A2A instead of one giant assistant. Gelato's ticket-triage agent and Workday's skill-based HR agent appear on the same Google Cloud list and match the pattern of narrow, testable agents, but that list does not say they were built with ADK, so treat them as examples of the shape rather than of the tool. (Our analysis.)

When to look elsewhere

If your data and identity live in AWS or Azure, the deployment advantage disappears and a framework-neutral choice such as LangGraph may be simpler. Teams without developers should look at hosted builders instead; ADK is code first. (Our analysis.)

A setup outline

  1. Start with one agent and one tool in the language your team already writes.
  2. Build an evaluation set from real historical cases before tuning prompts, as Gelato's triage results suggest.
  3. Split into multiple agents only when one agent's instructions start contradicting each other.
  4. Deploy to Cloud Run or your own containers and wire in tracing from day one.
  5. Add agent-to-agent calls last, with each agent's permissions kept separate.
