Markups.ai: how the agent works and how to build one like it

Summary: Markups.ai offers an email-in contract negotiation agent that returns redlines, per the source.

Source: https://cloud.google.com/transform/101-real-world-generative-ai-use-cases-from-industry-leaders source page fetched

Why this use case works

Using email as the interface removes adoption friction: lawyers and business people already send contracts by email. The output, a redline, fits existing review habits instead of requiring a new tool. (Our analysis.)

Agent pattern: Document-review agent

A document-processing agent: ingestion and OCR, extraction into a schema, rule or model-based review, and a human approval step before anything binding goes out. Audit logs are a requirement, not a nice-to-have.

How a smaller team could replicate it

Firms or in-house teams can encode their negotiation playbook (acceptable positions, fallbacks, red lines), have an agent produce a first-pass redline from it, and keep a lawyer as the final reviewer. (Our analysis, not a claim made by the source.)

Risks and guardrails

Risks: the agent conceding a position the client would never accept, and confidentiality of the draft contract. Guardrails: a written playbook with hard red lines, lawyer review of every redline before sending, and an enterprise data agreement with the model vendor. (Our analysis.)

What to measure

Time to first redline, percentage of agent edits accepted by the reviewing lawyer, and playbook coverage.
