Agents at Work #2: AI agents are getting a budget

Week of October 19–23, 2026 · about a 6-minute read

This week's theme: last week, agents got passports. This week, they got spending limits. Mastercard and Visa both showed AI agents paying for things inside limits a person set in advance, and Google and Databricks pitched new agent infrastructure on cost: token budgets and memory that stops agents from doing the same work twice. First, a real deployment where the agents handle contracts, not cash.

Deployment of the week: Birlasoft's Contract.ai obligation tracker

Birlasoft, a global technology firm, built Contract.ai, a multi-agent system on Microsoft Azure that reads master service agreements (MSAs), statements of work (SOWs) and related contract documents, then pulls out every commitment the delivery team has to meet. Per the Microsoft Source Asia feature (Oct 21):

  • Six specialist agents, coordinated by a planning agent, extract obligations, validate outputs and flag inconsistencies.
  • The system uses 335 metadata elements to interpret contractual context and link every requirement back to its original source.
  • It processes more than 1,000 SOWs a year and identifies an average of more than 10 obligations per project.
  • Birlasoft reports a "realized annual benefit of approximately 4,000 person-hours saved."

Caveats: these are Birlasoft's own figures, published in a Microsoft customer feature. The article doesn't say how the hours were measured or what the baseline was. Humans still review the output. As Birlasoft SVP Ramasubramanian S puts it: "These are obligations that have financial and legal implications, and we cannot let the agents run rogue on this."

What makes it work: one agent per contract type instead of one generalist, and every extracted obligation is traced back to the clause it came from, so a reviewer can check it. In one example, he says the system linked language on page two of a document to an obligation referenced on page 25.

Source: Microsoft Source Asia, Oct 21, 2026

This week in agentic AI

1. Mastercard opens early access to Agent Pay for Machines (Oct 20). Built on the open x402 protocol, it lets a business give an agent a task and a spending limit. When a paid service answers "402 Payment Required," the agent signs a payment voucher within its limit. At Cloudflare Connect, Mastercard showed a pilot with the agency Hype: an agent made nine payments to two independent merchants under one approved budget, "no separate accounts, API keys or invoices." Developers get buyer- and seller-side APIs, a sandbox and docs. Mastercard

Mastercard's framing, worth quoting: "Payments aren't the hard part. Authority is."

2. Visa, BILL and Billtrust launch a live pilot of agent-paid invoices (Oct 20). BILL's Payment Agent, registered through Visa's Trusted Agent Protocol, pays approved supplier invoices through Billtrust supplier portals. It uses tokenized card credentials instead of shared portal logins, and agent authentication can stand in for the CAPTCHA-style bot checks those portals use. According to the FAQ, the agent doesn't make payment decisions: it "only executes eligible payments that have already been approved by the buyer." The companies say the pilot is live and processing end-to-end transactions. Visa investor relations

3. Google announces Agent Compute Engine and token budgets for agents (Oct 22). Google says Agent Compute Engine, which gives each agent its own hardware-isolated microVM and already runs the Gemini agent, will be available in preview "in the coming months." It also announced token and cost governance for its Agent Gateway, which lets companies attribute spend and "enforce budget guardrails" across agents and models, plus model-routing policies. Google says both are coming this quarter in preview. Its open-source Agent Substrate for GKE claims "as much as 10x higher compute density" than traditional compute. Google Cloud blog

4. Databricks launches Agent Memory in Beta (Oct 20). Agent Memory is a managed memory layer on Agent Bricks that stores the facts, preferences and workflows an agent should keep, and runs a background pipeline to consolidate them. Databricks says that in internal benchmarks the architecture "tripled agent pass rate on real enterprise tasks while using 31% fewer tokens." In one example it gives, a question that took 11 tool calls and nearly six minutes took 2 tool calls and 41 seconds once the workflow was in memory. Databricks blog

The pattern (our take): the next control for agents is a budget. An identity says who the agent is; a budget says how much it can do. In the Mastercard and Visa announcements, a person approves the job and the limit, and the agent spends only inside those bounds. Google and Databricks are attacking the same problem from the cost side: token caps, and memory so an agent doesn't pay twice for the same answer. If you run agents at a small company, you don't need any of these products to start: give each agent a dollar or token limit per task and an approval step above it.

Tool spotlight: n8n

n8n is a workflow automation platform for building AI agents inside workflows you can see step by step. Per its own site, it offers 500+ native integrations, connects to any API over HTTP and to agents or coding assistants through MCP, and supports human-in-the-loop approvals, guardrails and evaluations. You can self-host it with Docker or use the hosted version. n8n also says it's a top-50 GitHub project with 208.2k stars.

A first build in the spirit of this week: new invoice email → AI step extracts vendor, amount and due date as structured output → if the amount is under your limit, log it to a sheet; if it's over, post to Slack and wait for a human to approve. That's the "approve once, then act within limits" pattern from the Visa pilot, at small-business scale.

How-to tip: give your agent a budget, not a card

Both payment announcements this week follow the same order of operations. You can copy it for any agent that spends money, tokens or API calls:

  1. Approve the job first. In Mastercard's pilot, the agent proposed a two-step plan and Hype approved the funding before the agent started paying. In the Visa pilot, the agent pays only invoices the buyer already approved.
  2. Scope the limit to the task. The Hype agent was limited "to the defined task and budget," not given open-ended spending authority.
  3. Never hand over shared logins. Visa's pilot uses tokenized credentials so buyers don't share supplier-portal passwords. In your own builds, give agents their own scoped keys, not a person's login.
  4. Keep the receipts. Visa's pilot lists visibility into the authorization and completion of each payment as a core feature. Log every agent action that costs money, with the task it belonged to.

If your automation tool has no budget feature, fake it: count calls or dollars in a variable, and route to a human approval step once the count passes your limit.
