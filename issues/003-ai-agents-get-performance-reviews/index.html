Agents at Work #3: AI agents are getting performance reviews

Week of October 26–30, 2026 · about a 6-minute read

This week's theme: in issue #1, agents got passports. In #2, they got budgets. This week, they got performance reviews. Salesforce, IBM, Monte Carlo and GitHub all shipped ways to test agents continuously, catch quality drops in production, and pull a misbehaving agent offline. First, a real deployment that learned the hard way why "no errors" doesn't mean "working."

Deployment of the week: Bayer Crop Science's Agentic Decision Engine

Bayer Crop Science built the Agentic Decision Engine (ADE), a multi-agent, natural-language layer over the platform its breeders, analysts and data scientists use to run hundreds of ML model configurations. A supervisor agent routes each question ("Why did my phenotyping workflow fail yesterday?") to a specialist agent, which pulls the answer from the right system. It runs on Amazon Bedrock AgentCore with LangGraph orchestration. Per the AWS post (Oct 23), co-written by Bayer and AWS staff:

  • ADE runs 22 specialist agents in production, each scoped to one domain with its own tools and data, and has been used by more than 100 users since its gated launch.
  • In its first phase, ADE resolves about 80 percent of user questions without an engineer in the loop.
  • With the Troubleshooting Agent, a diagnosis that "once took over an hour of manual log-hunting and waiting for engineer support now takes under 10 minutes."
  • Caching the stable prompt prefix (instructions and tool definitions) cut input-token cost by 20–30 percent.

Caveats: this is a vendor blog post co-authored by Bayer and AWS, and it promotes AWS services. The figures are first-phase results for a gated group of users, and the post doesn't say how the 80 percent was measured.

What makes it work: tight scoping. Each agent gets only its own tools and read-only permissions where possible (the Troubleshooting Agent can read operational data but "can't modify workflows"). The team also learned that its monitoring was lying to it: exception handlers "caught agent errors and returned responses that monitoring counted as successful." The fix was alarms on task failures, not just HTTP errors (more in the how-to tip below).

Source: AWS Machine Learning Blog, Oct 23, 2026

This week in agentic AI

1. Salesforce adds Agent Evals and a kill switch to Agent Fabric (Oct 27). Agent Evals auto-generates tests before deployment, then evaluates agents, LLMs and MCP servers in production against quality thresholds. When results fall short, it can trigger predefined interventions, including the Agent Kill Switch, "with approval where the team's policy requires it." Salesforce also added hard spending limits and says its Cost Optimization Policies cut token usage "by up to 75% (based on test scenarios)." Per Salesforce, the Agent Kill Switch and cost controls are generally available now. It says Agent Evals will be in beta in November 2026, with general availability expected in January 2027. Salesforce

Salesforce's own example: a retailer switches its order-support agent to a cheaper model, scheduled evals catch it giving wrong answers about delayed orders, and the agent is quarantined after a human approves.

2. IBM brings discovery, containment and evaluation to watsonx Orchestrate (Oct 27). At TechXchange, IBM said Orchestrate can now test agents, models and MCP servers for quality, accuracy and compliance before deployment, monitor them in production, and track each agent's model and token use. In tech preview, it can also find agents built on Amazon Bedrock, Microsoft Foundry and Google Gemini, and run agents in isolated sandboxes with a kill switch. HashiCorp Vault now issues short-lived credentials to agents and can revoke a session in real time if an agent tries something it isn't approved for. IBM's release says only 13% of organizations believe they have the right AI agent governance in place. IBM newsroom

3. Monte Carlo launches Bayes, an agent that fixes other agents (Oct 28). Bayes watches production traces and evals, triages alerts, and delivers agent fixes as draft pull requests or tickets for engineers to merge, then confirms the fix worked. Customers decide how much it handles on its own. Monte Carlo says a typical AI engineer can keep only "one to three agents" under real watch, and that Bayes helps enterprises detect "200% more incidents than their in-house systems, while flagging over 80% fewer false positive alerts." Those are the company's own figures. Monte Carlo via GlobeNewswire

4. GitHub Agentic Workflows is generally available (Oct 28). You write an automation (issue triage, CI failure analysis, docs updates, test writing) as a plain-language Markdown file, and it compiles to standard GitHub Actions YAML, run by Copilot or another coding agent. Agents run read-only by default inside a sandboxed container, and a dedicated threat-detection job scans proposed changes before they're applied. It's available on GitHub Free, Team and Enterprise; the default Copilot CLI engine requires a Copilot license. GitHub Changelog

The pattern (our take): the industry is moving from "deploy and hope" to "deploy and review." Every launch this week assumes agents will drift: a model swap, a changed API, bad data. The answer is the same in each case: test before launch, keep testing on live traffic, and decide in advance what happens when the score drops (alert, quarantine, kill). You don't need an enterprise control plane to do this. A spreadsheet of 20 real questions with known-good answers, rerun every time you change a prompt or model, gets a small team most of the way.

Tool spotlight: Langfuse

Langfuse describes itself as "an open-source AI engineering platform for agent evaluation and observability." Per its site, it records hierarchical traces of every LLM call, tool call and retrieval step; runs evaluators (LLM-as-a-judge, code checks or human review) on production data or experiments; and tracks cost and latency with dashboards and alerts. All product features are MIT licensed and self-hostable, and Langfuse says its cloud free tier includes 50k observations per month with no credit card required. It lists integrations with n8n, LangChain, CrewAI, OpenAI, Anthropic, Amazon Bedrock and more.

A first build in the spirit of this week: send your support agent's traces to Langfuse → build a dataset of 20 real customer questions with known-good answers → run it as an experiment every time you change the prompt or model → add an LLM-as-a-judge evaluator on live traces and an alert when scores or cost spike. That's Salesforce's "switch models, rerun evals" scenario at small-team scale.

How-to tip: count task failures, not just errors

Bayer's team found that its agent could fail while every request returned "success." Per the AWS post, here's what they changed, and you can copy it in any stack:

  1. Separate transport success from task success. A 200 response with a wrong or empty answer is a failure. Log whether the task completed, not only whether the call finished.
  2. Alarm on agent-specific failures. Bayer added custom metrics inside failure paths and alarms for tool-call errors, throttling, model timeouts and structured-output validation failures.
  3. Trace the whole chain. One question can become several model calls, tool calls and agent handoffs. Bayer's traces follow each request across the supervisor and specialists, so you can see which step changed the outcome.
  4. Treat model upgrades as a test, not a swap. Bayer tried a newer model and found its tool-use plus structured-output combination didn't work with how ADE's agents were built, so it kept the current model. Their principle: "A newer model is not automatically a drop-in replacement."

If your automation tool has no eval feature, start with step 1: add a final check step that validates the agent's output (required fields present, answer not empty) and routes failures to a human.
